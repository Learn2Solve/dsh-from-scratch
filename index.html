DeepSeek Harness
from Scratch

2026 年 8 月 13 日，DeepSeek 开源了 dsh。 我当天把它 clone 下来，第一次运行失败，第二次跑起来花了 474 毫秒。 然后花了一整天读它的两百个包，最后决定：与其继续读，不如在浏览器里把它重造一遍。 这就是那本书。

九章 + 一个横向对照附录 不需要 API key 不需要装任何东西 纯静态 HTML

§0.1先看成品

下面这个方块里跑的，是本书结束时你会得到的东西：一个能工作的 mini-dsh。 它有插件树、事件瀑布、只追加的会话日志、带守卫的工具流水线。 模型是脚本化的假模型，所以每次跑出来一模一样。除了模型，其余每一行都是真的在执行。

成品预览mini-dsh 执行一个任务

注意输出的层次。turn/start 开一个回合，回合里有若干个 step， 每个 step 是一次模型请求加上它触发的工具调用。工具结果回流之后模型欠一次新请求，于是下一个 step 开始。 没有更多要做的事，回合关闭。这个两层结构是 dsh 的骨架，第 1 章就会把它建起来。

§0.2为什么是这个 harness

市面上的 harness 长得都差不多。一个固定的内核，一张写死的工具表，靠 MCP 或者插件 API 往外挂东西。 你想改 agent loop 就得 fork，你想让两个会话用不同的工具集，通常改不了。

dsh 的做法是把整个产品拆成约两百个插件包，用一个叫 Cordis 的依赖注入内核串起来。 模型适配器是插件，工具注册表是插件，会话日志是插件。agent loop 自己也是插件。 它的架构文档里有一句挺硬的话：

There is no privileged core to patch: you extend dsh by mounting a plugin beside the others, and registrations are effects that unwind when their plugin unloads.

读到这句我的第一反应是"营销词"。等我自己实现过 ctx.effect() 的反序回收， 实现过 waterfall 事件不调 next() 就连内置行为一起否决， 实现过 surfaceOp 折叠出来的模型视图，才觉得这句话是字面意思。 这本书的全部目的就是让你也走一遍这个过程。

这个架构值不值它的复杂度，我到现在也没想清楚。两百个包不是小数目， isolate realm 那一段我每次读都要想三遍。所以下一节先把发布之后的真实反应放上来， 免得这本书读起来像软文。

对照真实源码 每章末尾有"回到真实的 dsh"，列出对应的真实文件路径。 git clone https://github.com/deepseek-ai/deepseek-harness.git 然后逐个对照。写作时对照的版本是 0.1.0-rc.6，提交 47f943859b。

这句话直接把"新颖"打了个折：热重载和动态装卸不是 dsh 发明的，Pi 已经有类似的东西， dsh 的区别是推得更远，一直推到 UI 组件。

好评也有，而且集中在同一个点上。kamranjon 和 bmurphy1976 都是冲着 Every Run is Traceable 去的： 系统提示、推理、工具调用、子 agent 调度、每一次上下文注入，全部落进一条只追加的事件流， resume、fork、search、replay 都在这条流上跑。 JonChesterfield 则说它的工具调用 JSON schema 比 codex 严格得多， 同时抱怨 git 藏在 bash 后面，只能靠 hope 或者沙箱兜着。

我的判断和这些人大体重合。第 5 章的会话日志是真东西，我会花最多篇幅在那一章。 "一切皆插件"是不是值这个价，我倾向于对研究和平台场景值，对"我只想要个能用的编码助手"不值。 书里两边都写。

HN 只是这件事的一小半。按一份覆盖发布后 48 小时的舆情检索，中文这边知乎单个问题就有 215 万浏览、366 条回答，B 站一条讲解视频接近 19.4 万播放；英文这边能对上的，是 r/LocalLLaMA 一条 258 赞的主帖，加 The New Stack 一篇记者稿。同一个仓库，两边讨论的量级不在同一个刻度上。

真跑过的人的说法比架构争论有用，但它们没有指向同一个结论。X 上的 @teortaxesTex 是西方少数几个连着做实测的账号，他先说 dsh 省 token："I think this would have already been a 600-700K tokens project in OMP or Reasonix"，几个小时后又补了一条，说它在长项目里 "slows to a crawl"， token 流慢到他只能杀掉窗口重开。知乎那条置顶实测同一天写的是另一头：源码装了 27 分钟， 让 DeepSeek Flash 写一个小插件，"洗个澡回来发现死循环了"，收尾是 "没有特别让我眼前一亮的地方"。

两边缺的是同一样东西。48 小时里没有一个人把 dsh 和 Claude Code、Codex、Pi、omp、OpenCode 放在同一个模型、同一个 prompt 上跑一遍可复现的对照。知乎一条 642 赞的评论就在要这个："我想知道你们精心考虑的测试 benchmark"。这本书也给不出，附录 §A.7 把这件事写进了标题：那一页比的是架构，不是效果。

还有一条线在社交媒体上几乎没露头：发布不到一天，GitHub Discussions 里落了两份独立的插件安全审计， Fz0x00 的 #454 和 xiejin77 的 #587，钉的正是本书对照的 0.1.0-rc.6 和同一个提交。两份的结论都分成两半：面向模型那一半被评为 production-grade， 面向插件那一半按审计自己的说法目前没有安全设计；两份也都写明这条路要用户自己去 dsh plugin add，不是零点击远程 RCE。附录 §A.6.4 逐条展开。

§0.4你会亲手造出什么

每一章往 mini-dsh 里加一块能跑的东西，不是加一段说明文字：

§0.5怎么读

按顺序。每章都依赖前一章的产物。第 5 章的会话日志要用第 4 章的事件系统， 第 9 章让模型现场挂插件，用的是第 3 章的 fiber 生命周期。

demo 可以反复跑，很多里面的代码框能直接改了再跑。改坏它比读懂它快。 把 next() 删掉看瀑布怎么断，把 disposer 注释掉看卸载之后残留了什么。 书里有好几处专门放了"把它弄坏"的按钮。

遇到 先猜再跑 的方框，先选一个再往下看。 选错的地方就是这个机制真正在教你东西的地方。

预备知识：会读 JavaScript，知道 async/await，用过任意一个 agent 编码工具。 不需要懂依赖注入，不需要懂事件溯源，这两样第 2 章和第 5 章从零讲。

最后一行是我写这本书期间反复刷新看到的。代码一行没动，star 涨了四万三。 但同一天 HN 主贴下面 234 条评论里，问得最多的是"这到底是个啥"。 star 数衡量的是好奇心，不是口碑，这两件事在这个项目上分得很开。

先看这个再动手 如果你机器上有多个 Node，npx 很可能抓到不对的那个。 我第一次跑就是这样：Homebrew 的 Node v23.6.0，没有 zlib.createZstdDecompress， 会话日志压缩包在插件树加载阶段直接 import 失败，报一个看起来毫不相干的 SyntaxError。 发布的 npm 包没声明 engines，所以 npm 连个警告都不给。 要求是 ^22.19 || >=24。先 node -v。
